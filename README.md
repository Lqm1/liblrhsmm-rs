# liblrhsmm-rs

This repository is a Cargo workspace containing `liblrhsmm-rs`, `liblrhsmm-rs-capi`, `liblrhsmm-rs-wasm`, `liblrhsmm-rs-node` and `liblrhsmm-rs-python` under `crates/`. See [workspace layout](docs/workspace-layout.md) for package selection, artifact names and binding commands. See [workspace split verification](docs/workspace-split-verification.md) for migration checks and their scope.

Native Node.js and Python packages are implemented with napi-rs and PyO3. See [Node.js](crates/liblrhsmm-rs-node/README.md), [Python](crates/liblrhsmm-rs-python/README.md) and [native binding verification](docs/native-bindings.md). Builds and tests do not publish packages.

An idiomatic Rust reimplementation of the complete public liblrhsmm functionality, licensed under GPL-3.0-or-later. Upstream: https://github.com/Sleepwalking/liblrhsmm.

The native Rust phase passes the agreed five-target acceptance gate. C ABI and browser/Node.js WebAssembly bindings implement all 103 original public function mappings, including both storage precisions and optional serialization. See [C API](docs/c-api.md), [WASM API](docs/wasm-api.md) and [binding inventory](docs/binding-inventory.csv). The accepted complete-task gates pass; evidence and deferred platform validation are recorded in [SHIRO requirements verification](https://github.com/Lqm1/shiro-rs/blob/main/docs/requirements-verification.md) and [execution checkpoint](https://github.com/Lqm1/shiro-rs/blob/main/docs/latest-execution-checkpoint.md). Owned model/data containers and model, standalone duration/GMM/stream, observation, segmentation, and dataset serialization are implemented. Flat-start model/stream constructors and incremental builders preserve C defaults; unfilled builder slots are rejected before use. Owned clones preserve GMM variance floors and independent segmentation storage. Model operations include single-component concatenation, duration conversion, highest-weight mixture splitting, and weighted duration log density. Prepared GMM likelihoods and weighted multistream log-density and density tables support the original boundary and diagonal pruning conventions. Annealed duration log densities and densities are exposed directly. Non-log tables have a separate type so they cannot be passed accidentally as log scores. Geometric-duration HMM forward/backward and Viterbi are implemented with the original quantized probability helpers. Explicit-duration HSMM forward and Viterbi support skip, self, and backward transitions through an immutable transition graph. HSMM backward and geometric HMM state/transition occupancies are implemented. HSMM duration/state occupancies and HSMM/HMM mixture occupancies are implemented, including the documented initial-state correction. Owned sufficient statistics, aligned initialization collection, and duration/GMM/stream/model maximization updates are implemented. HSMM and geometric HMM posterior expectation collection and single-utterance estimation are implemented. Synthetic tests connect two expectation/update iterations to saving, reloading, and inference. Aligned dataset regrouping and Viterbi path resegmentation are implemented. Model generation supports caller-owned RNGs and controlled uniform draws, preserving the original normal approximation and mixture selection. SHIRO integration exercises initialization, HMM/HSMM training, saving, reloading and inference. Binary64 model storage, densities, preparation, inference, posteriors, statistics and training are implemented; dataset regrouping, resegmentation and sample builders also retain binary64 precision. Generation also supports both precisions with caller-owned RNGs and controlled uniform draws. Both precisions read and write the original binary32 wire schema; saving double parameters intentionally rounds to that schema, as in C. Public configuration, ownership and numerical coverage are recorded in `docs/configuration-coverage.md`, `docs/ownership-coverage.md`, `docs/header-coverage.md` and `docs/binding-inventory.csv`. Per-function counts do not replace those field and configuration audits.

The default `serialization` feature enables the legacy codec and its optional rmp dependency. Disable default features for computation-only use; model/data storage, preparation, inference, learning, generation and dataset operations remain available. The model_roundtrip example requires serialization.

The model reader supports the historical GMM format used by SHIRO's pretrained model and the current format with per-dimension variance floors. The default writer produces the current C-readable format. `ModelEncoding::WithoutVarianceFloors` explicitly writes historical models and rejects nonzero variance floors rather than losing data.

The native phase passed the five agreed Windows/Linux x86 execution targets before binding implementation. The latest-source native and external C/Python refresh is recorded separately; deferred ARM64 and Python 32-bit execution are not claimed.

Sampling API references: https://docs.rs/rand/0.10.3/rand/trait.RngExt.html and https://docs.rs/rand/0.10.3/rand/distr/struct.OpenClosed01.html. Callers provide the RNG, so the library does not enable sys_rng or thread_rng. SmallRng and StdRng do not promise reproducible sequences across versions or targets; controlled uniform draws support explicit C comparisons.

MemoryPool provides append-only byte allocation with the original page growth and accounting. PoolAllocation handles keep regions addressable across growth; get/get_mut return borrowed slices and reject foreign handles. Exposed bytes are initialized, including allocate. Reference Rust APIs: https://doc.rust-lang.org/std/vec/struct.Vec.html#method.try_reserve_exact and https://doc.rust-lang.org/std/sync/struct.Arc.html#method.ptr_eq.

The numerics module exposes the original coefficient tables at both precisions. LOG_ADD_COEFFICIENTS and EXPONENTIAL_COEFFICIENTS, plus their _F64 counterparts, provide checked get/replace operations and allocation-free iteration. Replacements affect subsequent selected-precision helpers, inference and training process-wide, as with C's public arrays. Each coefficient preserves its bits through atomic access; concurrent table changes do not provide a whole-table or computation snapshot. Configure coefficients before starting a reproducible calculation. See docs/header-coverage.md for the source mappings and independent C comparisons.

ObservationSetBuilder and SegmentationSetBuilder support ordered incremental dataset construction. Model::prepare returns a borrowed PreparedModel with reusable emission normalizers and duration caches; PreparationOptions controls cache length, duration weight, and temperature. PreparedModel evaluates emission tables and runs HSMM forward/backward/Viterbi inference using these caches. Prepared inference requires matching temperature and duration weight. State and boundary pruning support fractional binary32 radii with the original C bounds. Header/build configuration coverage is tracked in docs/configuration-coverage.md.

Release checkpoints, package names and owner setup steps are documented in [the release procedure](docs/releases.md).
